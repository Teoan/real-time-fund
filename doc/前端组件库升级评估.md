## 3. 大版本迁移记录

### 3.1 react-day-picker 9 → 10

v10 移除了 v9 的兼容 API，本项目命中 2 处：

- `app/components/MyEarningsCalendarPage.jsx`：`toMonth` → `endMonth`。
- `components/ui/calendar.jsx`：`classNames.table` 已移除，改为 `month_grid`（并保留 `defaultClassNames.month_grid`）。
- `MyEarningsCalendarPage.jsx` 原有的 `month_grid: 'w-full'` 与 `table: 'w-full border-collapse table-fixed'` 合并为 `month_grid: 'w-full border-collapse table-fixed'`，保持 7 列等宽布局。

已确认 v10 仍保留：`Root.rootRef`、`Chevron`、`DayButton`、`WeekNumber`、`hideNavigation`、`captionLayout="dropdown"`、`dropdown_root`/`today` 等 key；`components.Button` 已移除但本地未使用。包名继续用 `react-day-picker`（v10 兼容），`@daypicker/react` 改名后续可选。

### 3.2 lucide-react 0.x → 1.x

- v1 移除全部品牌图标（Github/Figma/Slack 等）；项目 GitHub 图标是本地 SVG，无影响。
- 已核对在用 39 个图标在 1.67.0 全部导出（含 `AlertTriangle`、`HelpCircle`、`Loader2`、`MoreHorizontal`、`PlusCircle`、`TriangleAlert`、`Home` 等）。
- v1 默认给图标加 `aria-hidden="true"`：装饰性图标更规范；纯图标按钮仍需保留 `aria-label`/`title`。

### 3.3 framer-motion 12 → 14

官方升级指南：12 → 13 仅移除 `@emotion/is-prop-valid` 可选依赖（项目未使用 CSS-in-JS），14 无破坏性变更。因此仅升级版本，34 个文件的 `from 'framer-motion'` 不动。后续若要改为 `motion` 包 + `motion/react`，单独做。

### 3.4 shadcn CLI 3 → 4

- `components.json` 兼容：`new-york` 仍在新 schema 枚举中；`tsx:false`、`iconLibrary: "lucide"`、`registries: {}` 均有效。
- `shadcn/tailwind.css` 由 95 行增至 637 行，逐行比对确认**旧内容无删除、纯新增**（新 `@custom-variant`/keyframes），只影响 CSS 体积。
- CLI 要求 Node **>=20.18.1**，`engines` 已从 `>=20.9.0` 调整为 `>=20.18.1`（CI 的 Node 20 最新版、Docker 的 Node 22 均满足）。
- 新版 `new-york` registry 仍可取到新组件（`dropdown-menu`、`command`、`sheet`、`alert-dialog`、`card`、`avatar`、`item`、`kbd`、`input-group`、`button-group` 等均返回 200）。

### 3.5 TanStack Table 8 → 9

- 6 个文件从 `useReactTable` 迁到 `useTable` + `tableFeatures`：
  - 简单表（`FundHistoryNetValue`、`FundHistoryNetValueModal`、`FundDailyEarningsDetailModal`、`MarketTab`）**必须注册 `columnVisibilityFeature`**（详见下面的 v9 特性化 API 坑）；
  - `PcFundTable` 注册 `columnOrderingFeature`、`columnPinningFeature`、`columnResizingFeature`、`columnSizingFeature`、`columnVisibilityFeature`、`rowPaginationFeature` + `createPaginatedRowModel()`；
  - `MobileFundTable` 注册 column order/visibility/pinning + pagination。
- pinning 状态从 `left/right` 改为 `start/end`；`initialState.columnPinning` 必须同时提供 `start` 与 `end` 数组，否则 `orderByColumnPinning` 会因 `end.includes` 崩溃（移动端已修复）。
- `column.getStart('left')`/`getAfter('right')` → `getStart('start')`/`getAfter('end')`；`getIsPinned()` 返回值改为 `'start'|'end'`。
- `table.getState()` → `table.state`。
- 收益：React Compiler 相关 `incompatible-library` warning 消失，lint 从 55 → 50 warning；PC 固定列、列宽拖拽、分页与移动端渲染已用 headless Chrome 回归。
- **⚠️ v9 特性化 API 坑（2026-11-05 线上报错后修复）**：v9 把行/列方法挂到「特性」上，`row.getVisibleCells()` 属于 `columnVisibilityFeature`，核心只提供 `row.getAllCells()`。空 `tableFeatures({})` 下调用它会直接抛
  `TypeError: row.getVisibleCells is not a function`，而且**构建期完全发现不了**——只有表格真正渲染出数据行时才触发（`FundHistoryNetValue` 的「业绩走势」tab 就是这么崩的）。
  修复：4 个简单表全部改为 `tableFeatures({ columnVisibilityFeature })`；`MarketTab` 用模块级常量复用同一份 features。
  已补回归守卫 `app/components/__tests__/table-features.test.js`：用 `react-dom/server` 实测「空 features → undefined、注册后 → function」，并静态扫描所有 `app/components/**.jsx`，凡调用 `getVisibleCells` 却未注册该特性的直接失败。

### 3.6 Next 16.4.4 / ESLint 16.4.4 的新约束

1. **Turbopack 成为构建默认**：`next build` 由 webpack（基线 41s）变为 Turbopack（4.3s）。React 18 时代需要 `react-compiler-runtime`；升级 React 19 后改用内置 `react/compiler-runtime`，该包已移除。
2. **`eslint-config-next@16.4.4` 需要 `typescript`**：其 `typescript-eslint` 在加载时 `require('typescript')`；已加 dev-only `typescript@5.9.3`（不产生 `.ts` 文件）。
3. **新增 React Compiler 规则**：`eslint-config-next` 16.4 启用 `react-hooks/immutability`、`react-hooks/preserve-manual-memoization`、`react-hooks/purity`、`react-hooks/refs`，在存量代码中报 10 个 error。本轮在 `eslint.config.mjs` 将 4 条规则降级为 `warn`，保留可见性，代码改造单独跟进（涉及 `ModalsLayer` 的 ref 写入、`useRefreshManager`/`page.jsx` 的 `Date.now()` 渲染期调用等）。
4. **React 18 弃用提示已消除**：升级 React 19 后 Next 16 不再提示；React 19 同时满足 Next 17 的硬性要求。
5. **Sentry 10.78 弃用旧入口**：`withSentryConfig` 改从 `@sentry/nextjs/config` 导入，`next.config.js` 已更新。

### 3.7 React 18 → 19

- `react` / `react-dom` 从 18.3.1 升到 **19.3.1**；已核对 radix-ui、lucide、framer-motion、sonner、vaul、react-photo-view、dnd-kit、chartjs、TanStack、react-day-picker 的 peer 均支持 19。
- 移除 `react-compiler-runtime`：React 19 自带 `react/compiler-runtime`，Next 16 检测到 React 19 后把 Compiler target 设为 19；需清理 `.next` 缓存后再 dev/build，否则旧缓存仍会引用已删除的 shim。
- 验证：lint 0/50、build 成功；headless Chrome 桌面/移动端、设置弹框、命令面板、基金表格均无 error，无 React 18 弃用提示。
